# 语言语义在 LLVM 边界上的损失

前端必须在生成 LLVM IR 之前（或同时用元数据）决定许多语言级事实。IR 擅长表达控制流、标量数据流与显式内存访问；它不自动保留「这门语言里指针可以别名什么」「对象生命周期在哪条作用域结束」的完整故事。

## 进入 IR 时已经定型的东西

- **求值顺序与副作用切分**：哪些子表达式的副作用已排序进指令序列。
- **类型在运行时的去留**：单态化后的具体函数 vs 擦除后的统一表示，在 IR 里表现为不同的函数族或指针类型用法。
- **未定义行为的边界**：前端若把某运算标成 `nsw`（no signed wrap）等快速数学旗标，等于把「溢出不发生」交给优化器当公理用。

## poison、undef 与别名信息

LLVM 用 `poison` / `undef` 等概念表示某些异常值传播（细节以 LangRef 为准）。优化通道会利用这些规则删除或合并指令。TBAA（type-based alias analysis）元数据、`noalias` 参数属性等告诉优化器「这些指针不别名」；信息来自前端对语言规则的翻译。前端标错或标过强，等于把语言里未保证的命题交给优化器，表现可以是「合法源码被优化坏」或「优化不够大胆」。

生命周期相关的 `lifetime.start` / `lifetime.end` intrinsic 帮助优化栈槽重用；它们同样是前端插入的契约，不是 CPU 的硬件事实。

## 口试用法

举一例即可：C 有符号加法带 `nsw` 后，溢出路径可被当成不可达；或 `restrict` / `noalias` 使两次内存访问被重排。重点是：**争论优化是否合法时，要问前端在 IR 上留下了什么假定**，而不是只看最终汇编像不像源码。
