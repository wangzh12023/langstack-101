# 编译器与 LLVM

本章回答一条链：高级语言源码如何变成上一章那种可反汇编的机器码，以及 **LLVM** 在这条链里占据哪一段。

```mermaid
flowchart LR
  Src[源码] --> Fe[前端]
  Fe --> IR[LLVM IR]
  IR --> Mid[中端优化]
  Mid --> Be[后端]
  Be --> Obj[目标文件 / 汇编]
```

前端负责词法、语法与语义，把程序变成某种中间表示（IR）。中端在 IR 上做与具体 CPU 关系较弱的变换。后端做指令选择、寄存器分配与机器相关的收尾，再交给汇编器与链接器。LLVM 提供一套可共享的 IR、优化通道和可重定向后端；clang、rustc（经由 LLVM）、部分其他语言前端把语义 lowering 之后交给它。

## 本章阅读顺序

先建立「为何需要 IR」，再读 [LLVM IR 核心概念](llvm-ir.md) 与 [SSA 形式与 φ 节点](ssa.md)，随后看优化与后端轮廓。调用约定如何在 LLVM 里落地、语言语义在进入 LLVM 时丢掉了什么，分别见专页；这两页直接对应口试量规里关于 lowering 与语义边界的问题。

实验页 [从 C 到 LLVM IR 到目标码](c-to-asm-lab.md) 用同一份 fibonacci 把 `-O0` / `-O2` 的 IR 与 asm 对照起来。读完应能指着一段 IR 说明基本块与 SSA 名字，并解释为何优化后调试器对不上原来的局部变量。

## 深度边界

本章目标是**读懂与解释**，不是向 LLVM 贡献后端。指令选择与寄存器分配讲问题和经典思路；TableGen 与 MachineInstr 细节只在后端页末节点到存在性。JIT（ORC 等）在 [求值与执行模型](../ch04/evaluation.md) 里从语言实现角度出现，不在这里铺 API。
