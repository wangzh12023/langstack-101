# 性能数字的读法

以 [naive fibonacci 跨语言对照](https://benjdd.com/languages/) 一类页面为材料：同一输入、相近算法外形、墙钟时间差距可以到数量级。数字本身只说明「在该环境、该实现、该旗标下跑了这一次」；要把差距谈成机制，需要拆开基准实际施加的压力。

## 递归 fibonacci 施加的压力

朴素 `fib(n) = fib(n-1)+fib(n-2)` 的调用次数随 \(n\) 指数增长，叶子极多。它首先敏感的是：

- 调用约定与栈流量：传参、保存寄存器、栈帧建立是否便宜
- 是否被优化成迭代或常量折叠；尾递归是否存在、是否被利用
- 整数语义：固定宽度溢出、任意精度、是否隐式装箱
- 运行模式：解释执行、字节码派发、JIT 是否已升温、AOT 是否内联打开

名次往往反映这条递归路径上谁更接近少量机器指令，并不自动代表一般负载下的抽象代价。

## 追问清单

读任何一张语言排行表时，按条追问：

1. 测的是稳态还是包含进程启动、JIT warmup、第一次导入？
2. 默认整数类型宽度与溢出规则是什么？Python 的 `int` 与 C 的 `int` 不是同一运算。
3. 编译旗标与运行时版本？`-O0` 与 `-O2`、debug 与 release、解释器与 JIT 打开与否。
4. 算法是否仍是同一控制流？优化器是否合法地改写了递归。
5. 分配与 GC：这条路径上有没有堆分配；若有，时间是否算进停顿。
6. 对照是否公平到 ABI 边界：是否允许改用迭代、查表或内建大整数。

这类对照适合用来追问机制：从时间差回到调用约定、表示与执行模型。跨语言机制对照见 [跨语言对照表](../ch05/cross-language-matrix.md)；
