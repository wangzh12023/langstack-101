# 浮点与舍入

浮点把实数映到有限位模式，用「科学计数法」换动态范围：相近的小数能区分，极大或极小的数靠放大指数表示。IEEE 754 规定了二进制格式、舍入、特殊值与例外；主流 CPU 与语言的 `float`/`double` 都落在这套标准上。整数补码是精确的模运算；浮点运算每一步都可能舍入，结合律与分配律不再成立。

## IEEE 754 二进制格式

常用两种：binary32（单精度，`float`）与 binary64（双精度，`double`）。布局均为：1 位符号、\(E\) 位指数、\(M\) 位尾数（小数域）。binary32：\(E=8\)，\(M=23\)；binary64：\(E=11\)，\(M=52\)。指数用偏移码（bias）：binary32 的 bias 为 \(127\)，binary64 为 \(1023\)。规格化数的值可写为

\[
(-1)^s \times (1.m)_2 \times 2^{e-\mathrm{bias}}
\]

其中 \(m\) 是尾数比特给出的小数部分；隐藏的前导 `1` 不占存储。全零指数表示非规格化数与零；全一指数表示无穷与 NaN。符号位使 \(+0\) 与 \(-0\) 可区分，比较时通常视为相等。

精确可表示的数是离散集合。例如 binary64 在 \(1\) 附近，相邻两数间距（单位舍入 ulp）为 \(2^{-52}\)；到 \(2^{53}\) 量级，间距变为 \(2\)，奇数整数已无法精确表示。这直接解释了 JavaScript `Number`（即 binary64）的「安全整数」上界 \(2^{53}-1\)：超出后「整数运算」也会丢精度。

## 舍入

默认舍入模式多为**就近偶数**（round to nearest, ties to even）：结果落在两可表示数正中间时，选最低有效位为 0 的那一侧，避免统计偏差。其他模式包括向零、向 \(+\infty\)、向 \(-\infty\)；数值库与部分语言可改舍入，但应用代码极少改全局模式。

一次加减乘除：先按无限精度算精确数学结果，再按当前模式舍入到目标格式。因此 `0.1 + 0.2` 在 binary64 里通常不等于 `0.3` 的字面表示——字面量 `0.1` 本身已是对实数 \(1/10\) 的近似。比较浮点应用容差或整数化后的精确路径，而不是依赖 `==` 在十进制直觉上成立。

融合乘加（FMA）一次乘加只舍入一次，结果可与「先乘后加、两次舍入」不同。编译器在许可（如 `-ffast-math` 或显式 FMA）下改写表达式时，数值会变；基准若对位要求可复现，需固定是否允许 FMA。

## 结合律失效

实数加法满足 \((a+b)+c = a+(b+c)\)。浮点加法不满足：大数加小数时，小数可能被吞掉。经典例子：令 \(a=10^{16}\)，\(b=-10^{16}\)，\(c=1.0\)（binary64）。则 `(a+b)+c` 得 `1.0`，而 `a+(b+c)` 得 `0.0`，因为 `b+c` 在 \(10^{16}\) 量级下仍是 \(b\)。并行归约、改变循环展开顺序、向量化重排加法树，都会改变结果比特，即使算法「数学上」相同。

乘法与加混合时，分配律同样失效。优化器若启用「快速数学」假设（忽略 NaN/Inf、重联想、消除多余舍入），可生成更快但数值不同的代码。语言默认是否允许这类变换不同：Fortran 传统上较松；C/C++ 默认较严，靠旗标放松；Java 对浮点重排限制更严以换可复现性。读基准时，同一语言不同编译旗标也可能让 float 核函数的结果与周期一起变。

## 特殊值与谓词

除以零（在浮点语义下）可产生 \(\pm\infty\)；无效运算产生 NaN。NaN 与任何值（含自身）的相等比较为假，故 `x == x` 可用于探测 NaN。有序比较与无序比较在指令集上分家（如 x86 的 `ucomisd` vs `comisd`）；语言里的 `<` 对 NaN 的行为需查规范。刷新（flush-to-zero）与非规格化数缓慢处理是微架构细节：大量非规格化运算会拖慢数值核，有时被误读成「算法变慢」。

误差分析在工程上常用 ulp 或相对误差，而不是「小数点后几位」。两次舍入的复合运算，最坏误差可大于单次 0.5 ulp；长链累加用 Kahan 补偿或更高精度累加器，是在接受 IEEE 运算的前提下减小发散，而不是恢复实数结合律。库函数（`sin`、`exp`、`pow`）的 ulp 误差界与是否保证正确舍入，属于 libm 契约，与硬件加减乘除的 IEEE 保证分层：后者由 CPU/FPU 落实，前者由软件近似。

## 基准里的浮点路径

跨语言「同一算法」若实际类型不同，数字不可横比：

- 一侧用 `double` 累加，另一侧用 `float` 或定点数，既改精度又改吞吐（SIMD 宽度、端口压力不同）。
- 一侧用整数算 fib，一侧因语言默认 `Number`/`float` 走浮点，比较的是不同功能单元与不同舍入。
- 归约顺序被并行或向量化改写，校验和比特不一致时，需区分「实现错误」与「合法重联想」。
- JIT 语言在 warmup 前后可能从解释态的软浮点/装箱，切到标量或 SIMD 机器浮点，墙钟时间含编译与去优化。

读性能数字时，先确认：类型宽度、是否允许 `-ffast-math` 同类选项、是否测到了 NaN/非规格化边界、归约是否要求确定性。整数路径的环绕与 UB 见 [比特与整数编码](bits-integers.md)；此处对应的是舍入与重排。

SIMD 路径把多个 float/double 打进向量寄存器，吞吐上升，但水平归约的树形加法再次引入结合顺序选择；「标量结果」与「向量结果」比特不一致时，先查是否允许重联想，再查是否有 bug。混合精度（用 `float` 算、用 `double` 累加）在深度学习与科学计算里常见，基准标题若只写「同一公式」而不写类型，排名无意义。

!!! note "与整数的对照"

    整数：位宽内运算可精确，溢出是环绕或 UB。浮点：几乎每次运算都可能舍入，溢出趋向 \(\pm\infty\)，下溢趋向零或非规格化。两者都是有限表示；失败模式不同，不能共用同一套「对不对」的口头标准。
