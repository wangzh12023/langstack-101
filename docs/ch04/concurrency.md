# 并发模型：线程、async、actor、CSP

并发模型回答三件事：谁在并行推进、共享状态如何同步、阻塞时发生什么。硬件侧的乱序与 store buffer 见 [存储缓冲与内存序](../ch01/memory-ordering.md)；本页固定语言/运行时层的分类轴。

## 操作系统线程

一对一映射到内核线程（或近似）。共享地址空间，同步靠互斥锁、条件变量、原子操作。上下文切换与栈内存成本由内核与运行时共同承担。C/C++/Rust 的原生线程、Java 的平台线程属于此路。

## 用户态调度与 M:N

Go 的 goroutine、部分 Erlang/Java 虚拟线程实现把大量轻量任务多路复用到较少的 OS 线程上。阻塞点（I/O、channel、停车场）由运行时切入调度器。对话时要分清：语言里的「线程」是内核实体还是可让出的用户态任务。

## async / await 状态机

编译器把异步函数切成状态机：遇 `await` 挂起并返回轮询/可完成对象，完成后续跑。执行仍落在某种执行器（线程池、事件循环）上。Rust `Future`、C#/JS/Python asyncio、Kotlin 协程同属「语法糖 + 状态机 + 执行器」结构；取消、本地线程亲和与 `Send` 一类约束因语言而异。

## CSP 与 actor

CSP 风格用 channel 传递消息，降低共享内存频率（Go channel、部分 CSP 库）。Actor 把状态封在邮箱后面的串行处理里（Erlang/Akka）。两者仍可能在运行时内部用共享内存实现；模型约束的是**程序员默认可见的共享方式**。

## 数据竞争与竞态条件

**数据竞争**（定义随语言而变）：冲突的并发内存访问，且缺少语言认可的同步；C++ 把数据竞争定为 UB，Java 则另有 JMM 下的有定义但可能令人惊讶的行为。**竞态条件**更宽：结果依赖调度时序，即使每次访问都有同步，逻辑仍可能错。讨论锁与 `atomic` 时先对齐谈的是哪一个。

内存序关键字（`memory_order_*`、`volatile` 在 Java 与 C 中含义不同）是在语言层把 [硬件内存序](../ch01/memory-ordering.md) 收成可移植契约；不会自动消除业务层的竞态。
