# 类型、内存、执行方式

比较语言时，常用的三条轴是：类型检查发生在何时、对象如何分配与回收、代码以解释、字节码还是机器码执行。

### 检查发生的时间

**静态类型**在编译期（或加载前）按规则检查，运行时可以擦掉部分或全部类型信息。**动态类型**在运行期对值做检查或走失败路径。**渐进类型**（如 TypeScript、带注解的 Python）允许部分静态检查，但运行时语义往往仍由底层动态语言决定——TypeScript 擦除类型后留下 JavaScript。

「强/弱」口语容易打架：对话时改说**是否暗黙转换**、**是否允许绕过检查的内存解释**（如 C 的指针转换），比贴强弱标签清楚。

### 名义与结构

**名义类型**靠声明的名字与继承关系认同（Java 类）。**结构类型**靠字段/方法形状认同（部分 Go 接口满足方式、TypeScript 接口）。实现上，名义类型常指向明确的运行时类型对象；结构类型的满足关系可能在编译期消掉，或生成适配器。

### 擦除与单态化

**类型擦除**：泛型实例共享一份代码，运行时看不到 `T`（Java 泛型典型）。代价是装箱、无法特化指令序列。**单态化**：为每个具体类型生成一份代码（C++ 模板、Rust 泛型默认策略）。代价是码膨胀，收益是可内联、可按类型优化。同一套「泛型算法」在两种策略下的基准与二进制体积不可直接比。

### 推断

类型推断减少标注，不改变「静态还是动态」：Hindley–Milner 一类推断仍在编译期完成。推断失败与动态语言里的运行时 `TypeError` 不是同一层现象。

导师若问「这门语言的类型在运行时还在吗」，先答擦除还是具体化，再答派发是否依赖运行时类型对象。

程序里的对象要有明确的分配位置与释放责任。主流策略——手动、所有权、引用计数、追踪式 GC——可以放在同一轴上比较；混用时（例如 GC 堆里嵌手动离堆缓冲）成本出在边界上。

### 手动管理

C 式 `malloc`/`free`：程序员决定寿命。错误模式是 use-after-free、double-free、泄漏。优点是可控、无 GC 停顿；代价是正确性压力与碎片。C++ 用 RAII 把释放绑到作用域，仍属手动谱系上的结构化写法。

### 所有权与借用

Rust 把唯一所有者与借用检查放进编译期：移动语义转移所有权，共享借用与可变借用互斥。堆分配（`Box`/`Vec` 等）仍是显式的，但释放点由所有者离开作用域决定。数据竞争在安全子集里被类型系统拒绝；`unsafe` 重新打开手动契约。

### 引用计数

每个对象带计数；指针复制增、销毁减，到零释放。Swift ARC、部分 Objective-C、CPython 主路径属此类。环需要弱引用或周期检测。赋值路径上的原子增删计数可成热点。

### 追踪式 GC

见 [追踪式 GC 机制轮廓](gc-mechanics.md)。程序员不写 `free`，代价转移到分配器、屏障与停顿模型。

### 栈与逃逸

短寿命值优先放栈。若引用逃逸出函数（返回指针、存入全局/堆），编译器或运行时必须改到堆上——Go 的逃逸分析、Java 的标量替换/逃逸分析、Rust 的生命周期拒绝非法逃逸，都是在谈同一几何问题的不同解法。

追踪式垃圾回收从一组根（栈上引用、全局、寄存器）出发，沿指针到达的对象视为存活，其余回收。Java、Go、C# 等托管运行时的堆核心落在这一族；实现细节各异，共同的关键块是分配、标记、搬迁与写屏障。

### 标记与清扫 / 复制 / 分代

**标记-清扫**给可达对象打标，再回收未标记区域。**复制式**把存活对象搬到另一半空间，天然压缩碎片。**分代**观察「大多数对象朝生夕死」：年轻代频繁小回收，老年代少而贵。晋升策略与记忆集（remembered set）记录跨代指针。

### 写屏障

并发或分代 GC 在程序写指针时插入 **写屏障（write barrier）**：把「旧代指向新代」或「标记期间的指针更新」记入数据结构，以免漏标。屏障是托管代码里隐式额外存储/分支的来源之一；微观基准里给字段赋值的成本有时来自这里，而不是赋值本身。

跨代漏标的典型几何：老年代对象 `old.f = young` 时，若年轻代收集只从根与年轻代扫描，而不同步记录这条跨代边，`young` 会在仍被 `old` 引用时被当成垃圾。写屏障在赋值时把 `old` 记入记忆集（或卡表脏页），年轻代收集额外扫描这些源。并发标记下的三色抽象有同类问题：黑对象在标记过程中被改写成指向白对象，若无屏障或增量更新协议，白对象可能漏标；具体颜色约定随实现而变，要点是「指针写入会破坏已扫描集合的封闭性，因此要记账」即可。

### 停顿与并发

停顿式 GC 在回收时停止应用线程（STW）。并发/增量标记把工作摊到应用运行期间，仍可能有短停顿，并依赖屏障与染色不变量。讨论「有没有 GC」时，追问的是停顿模型与吞吐，而不是品牌名。

### 与 RC / ARC 对照

引用计数在赋值时维护计数，回收可更及时，但形成环时计数不归零，需要弱引用或周期收集器补洞。Swift ARC、CPython（主路径 RC + 周期 GC）属于此侧。追踪式 GC 不靠环计数，但付出扫描与屏障成本。写屏障解决的是追踪过程中的漏标与跨代漏记；环是 RC 的结构问题。

「语言跑起来」至少有四条常见路径——解释、字节码虚拟机、JIT、AOT；基准数字往往落在不同路径的不同阶段上。

### 解释

解释器直接遍历 AST 或某种线性化表示，按节点派发操作。实现简单，热路径上的派发与装箱开销大。教学用解释器与早期实现常见此模型；现代生产语言很少停留在纯 AST 解释。

### 字节码虚拟机

前端把源码编成紧凑的字节码，VM 循环取指派发。Java 的 `.class`、CPython 字节码、CPython 之外的许多语言（Ruby YARV、PHP Zend、早期 JS 引擎）都走这类结构。字节码比 AST 密、比机器码可移植；派发方式（巨型 switch、计算 goto、线程化代码）影响解释器上限。

### JIT

运行期把热点字节码或 IR 编成机器码，按剖面信息投机优化（类型反馈、内联缓存、去优化）。HotSpot、V8、.NET RyuJIT、LuaJIT 等属于此族。墙钟时间包含：**解释/基线编译阶段**与**升温后的稳态**。基准若只跑一次短任务，可能主要在测启动与 warmup，而不是峰值代码质量。

### AOT

运行前生成机器码：经典 C/C++/Rust/Go 工具链，或 Android 上的 ART AOT、Dart 发布模式等。优点是启动与峰值可预期；缺点是缺少（或仅有有限的）基于剖面的运行期重编译。LTO/PGO 把一部分「像 JIT 才有的」信息搬回 AOT 管道。

### 对照时的说法

同一算法在 C 与 Python 上差两个数量级，通常同时叠了：执行模型（机器码 vs 字节码循环）、整数表示、调用与分配。把差距说成「Python 慢」而不拆模型，解释力不足。语言分论页会标明默认管线；跨语言表汇总同一 fib 路径上各自压到了哪一层。
