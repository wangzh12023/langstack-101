# 互操作与 FFI 边界

外语函数接口（FFI）把两种语言的调用接到同一条机器调用约定上。失败通常不是「语法翻译错了」，而是 ABI、所有权、异常与线程模型在边界上不一致。

## 调用约定与符号

两侧必须就下列事项达成一致：参数与返回值占用哪些寄存器/栈槽、结构体如何拆分或经隐藏指针返回、栈对齐、名称修饰（`extern "C"` 去掉 C++ mangling）。Linux x86-64 上与 C 互操作时，默认对齐 [System V AMD64 ABI](../ch02/sysv-amd64-abi.md)。写错一个整数参数位置，表现为「读到垃圾」而不是链接失败。

动态库还要保证符号可见性与依赖库装载顺序；`dlopen` / 绑定方式见 [位置无关代码与动态链接](../ch02/pic-dynamic.md)。

## 所有权与寿命

谁分配、谁释放、指针能活多久，必须在边界上显式约定。常见模式：调用方分配、被调方写入；被调方分配、调用方按对方规则释放（`free`、`CoTaskMemFree`、语言专用 dealloc）；或只借用不转移所有权（只读借用跨越调用期间保持存活）。Rust 的 `unsafe` FFI、Go 的 `cgo`、JVM/JNI 的局部/全局引用，都是在把这套契约编码成 API。

把托管对象的内部指针传给可能持有它的 C 代码，却未钉住（pin）或延长寿命，会在 GC 搬迁或收集后变成悬空指针。

## 异常、panic 与 errno

C 的错误多用返回值与 `errno`。C++ 异常、Rust panic、Java 异常不能安全地穿越未约定的外语栈帧：中间帧缺少匹配的展开表或人格（personality），会导致终止或破坏状态。跨边界要么换成错误码，要么保证整条栈都由同一种展开 ABI 建成。

## 表示与线程

结构体填充、端序、回调的线程（是否在持有锁时调用、是否要求主线程）同属 FFI 表面。Go 调用 C 可能阻塞 OS 线程；JNI 要求按线程附加 JVM。基准里「一层 FFI 包装」的成本往往来自编组（marshalling）、拷贝与线程切换，而不只是一次 `call`。
