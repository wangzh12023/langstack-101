# 求值与执行模型

「语言跑起来」至少有四条常见路径——解释、字节码虚拟机、JIT、AOT；基准数字往往落在不同路径的不同阶段上。

## 解释

解释器直接遍历 AST 或某种线性化表示，按节点派发操作。实现简单，热路径上的派发与装箱开销大。教学用解释器与早期实现常见此模型；现代生产语言很少停留在纯 AST 解释。

## 字节码虚拟机

前端把源码编成紧凑的字节码，VM 循环取指派发。Java 的 `.class`、CPython 字节码、CPython 之外的许多语言（Ruby YARV、PHP Zend、早期 JS 引擎）都走这类结构。字节码比 AST 密、比机器码可移植；派发方式（巨型 switch、计算 goto、线程化代码）影响解释器上限。

## JIT

运行期把热点字节码或 IR 编成机器码，按剖面信息投机优化（类型反馈、内联缓存、去优化）。HotSpot、V8、.NET RyuJIT、LuaJIT 等属于此族。墙钟时间包含：**解释/基线编译阶段**与**升温后的稳态**。基准若只跑一次短任务，可能主要在测启动与 warmup，而不是峰值代码质量。

## AOT

运行前生成机器码：经典 C/C++/Rust/Go 工具链，或 Android 上的 ART AOT、Dart 发布模式等。优点是启动与峰值可预期；缺点是缺少（或仅有有限的）基于剖面的运行期重编译。LTO/PGO 把一部分「像 JIT 才有的」信息搬回 AOT 管道。

## 对照时怎么说

同一算法在 C 与 Python 上差两个数量级，通常同时叠了：执行模型（机器码 vs 字节码循环）、整数表示、调用与分配。把差距说成「Python 慢」而不拆模型，经不起追问。语言分论页会标明默认管线；跨语言表汇总同一 fib 路径上各自压到了哪一层。
