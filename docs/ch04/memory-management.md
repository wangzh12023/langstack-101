# 内存管理轴

程序里的对象要有明确的分配位置与释放责任。主流策略——手动、所有权、引用计数、追踪式 GC——可以放在同一轴上比较；混用时（例如 GC 堆里嵌手动离堆缓冲）成本出在边界上。

## 手动管理

C 式 `malloc`/`free`：程序员决定寿命。错误模式是 use-after-free、double-free、泄漏。优点是可控、无 GC 停顿；代价是正确性压力与碎片。C++ 用 RAII 把释放绑到作用域，仍属手动谱系上的结构化写法。

## 所有权与借用

Rust 把唯一所有者与借用检查放进编译期：移动语义转移所有权，共享借用与可变借用互斥。堆分配（`Box`/`Vec` 等）仍是显式的，但释放点由所有者离开作用域决定。数据竞争在安全子集里被类型系统拒绝；`unsafe` 重新打开手动契约。

## 引用计数

每个对象带计数；指针复制增、销毁减，到零释放。Swift ARC、部分 Objective-C、CPython 主路径属此类。环需要弱引用或周期检测。赋值路径上的原子增删计数可成热点。

## 追踪式 GC

见 [追踪式 GC 机制轮廓](gc-mechanics.md)。程序员不写 `free`，代价转移到分配器、屏障与停顿模型。

## 栈与逃逸

短寿命值优先放栈。若引用逃逸出函数（返回指针、存入全局/堆），编译器或运行时必须改到堆上——Go 的逃逸分析、Java 的标量替换/逃逸分析、Rust 的生命周期拒绝非法逃逸，都是在谈同一几何问题的不同解法。
