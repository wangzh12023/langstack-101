# Python、JavaScript 与其他动态运行时


动态类型与解释/字节码路径会把「一次加法」变成完全不同的机器故事。先读 Python 与 JS/TS，再看 Ruby/PHP/Dart/R 作为同一类问题的四个样本，避免目录里再并列四套平行百科。


![Python](../assets/svg/python.svg){ width="40" }


CPython 把源码编成字节码，由求值循环解释执行；对象模型以堆上 `PyObject` 为准，主回收路径是引用计数，辅以周期检测。同算法相对 C/Rust 出数量级差距时，通常同时叠了字节码派发、装箱整数、函数调用约定与分配，而不是单一「解释器税」。轴见 [求值与执行模型](../ch04/evaluation.md)、[内存管理轴](../ch04/memory-management.md)、[对象布局](../ch04/object-layout.md)。

### 实现谱系与执行管线

`.py` → 编译 → `.pyc` 中的码对象；帧对象持有局部变量、操作数栈与指令指针。求值器按操作码派发（历史巨型 `switch`，近期特化解释器/自适应字节码在热点处改写操作码、缓存负载）。默认管线是**解释**，不是 JIT；PyPy 走元追踪 JIT，GraalPy 等另有路径——读基准必须声明实现，见执行模型轴上「测的是哪一段」。

调用一次 Python 函数：创建（或缓存复用）帧、解析参数、可能的闭包单元格访问；相对 C 的 `call` 重几个数量级的簿记。内建与 C 扩展函数走不同入口，但仍经对象协议（`PyObject*` 参数）。`async`/`await` 把协程对象交给事件循环；字节码层是发送/产量式状态机，调度在库侧。

### 内存与对象表示

一切可见值几乎都是堆上对象，带头：`ob_refcnt` 与 `ob_type`（`PyObject_HEAD`）。类型对象描述槽函数（读写属性、下标、调用、数值协议）。小整数与部分永生对象在 CPython 里缓存或永生化，但语义上仍是对象。`int` 为任意精度：小值有快速路径，大值走数字节数组；fib(40) 一类仍可能停在单字快速路径，但「整数 = 机器寄存器」绝不成立。

列表是指针数组（加过分配）；元组类似但不可变；字典为开放寻址哈希表，键值皆为对象指针。属性查找经类型字典与描述符协议，实例 `__dict__` 或键共享字典布局影响内存。装箱无处不在：把三个整数放进列表即三个对象指针 + 可能的对象本体，见布局轴上的装箱讨论。

回收：主路径 RC；形成环时计数不归零，由周期 GC 探测，见 [RC 与追踪对照](../ch04/gc-mechanics.md)。`__del__` 与周期回收的交互可推迟释放。赋值即改计数；多线程下全局解释器状态使计数操作与对象模型绑在同一把大锁叙事上（见下节）。

### 并发与运行时调度

CPython 的 **GIL**（全局解释器锁）保证同一时刻大致只有一个线程在执行 Python 字节码：线程可做 I/O 释放 GIL，或在 C 扩展中显式管理，但 CPU 密集的纯 Python 多线程近乎串行。多进程、`concurrent.futures`、或释 GIL 的数值库是绕行路径。模型归类上仍是 OS 线程 + 运行时大锁，见 [并发模型](../ch04/concurrency.md)。

`asyncio` 在单线程事件循环上协作式调度协程；CPU 密集任务仍需线程/进程卸载。自由线程/无 GIL 构建是实验与演进方向；对话时声明 CPython 版本与是否启用自由线程，避免把路线图当成默认生产语义。

### 与 C / ABI 的边界

**CPython C API** 与 **stable ABI**、以及 **cffi** / **ctypes** / **pybind11** / **Cython** 构成主要出入口。扩展模块是以 `PyObject*` 协议说话的动态库：创建对象要负责计数，偷引用（stolen reference）与借引用（borrowed reference）约定错误会导致泄漏或 double-free。这是 [FFI](../ch04/ffi.md) 所有权问题在 Python 上的日常形态。

`ctypes` 按 C 调用约定加载符号，把 Python 对象编成 C 类型；方便但易在指针寿命与线程上出错。NumPy 等把大块缓冲区放在非 Python 对象堆上，经 buffer protocol 借出；此时性能来自「离开对象循环」，而不是字节码变快。从扩展回调 Python 必须持有 GIL（经典构建）；持锁进 Python 再调回可能阻塞的 C，会造成死锁。

异常在 Python 侧是对象；跨 C 边界用返回值 `-1` + 设置异常状态传递，而不是 C++ 异常穿透。

### 影响正确性与性能的语义

[类型系统](../ch04/typing.md) 以运行时类型为准；注解默认不改变执行（除非导入检查器或运行时类型系统）。渐进类型落在工具链，不在 VM 指令集。查找属性与运算符重载经协议槽，稳态也有缓存，但相对单态化机器码仍厚。

整数永不「溢出变 UB」：自动扩成更大整数，fib 类算法在深度或数值变大时复杂度与分配特性改变。布尔是整型子类；`True`/`False` 是单例。容器迭代时修改结构会抛运行时错误；这是语义检查，不是 UB 轴上的抽象机问题。

全局与闭包名字查找、动态替换类型与猴子补丁，使内联与固定偏移负载变难——相对 Java JIT 的类型反馈，CPython 主要靠特化字节码与属性缓存。基准陷阱：用 C 扩展重写内核后宣称「Python 很快」，实际测的是扩展内的 C 循环；应用层仍可能停在对象协议上。

### 导师对话笔记

- 同算法数量级差：拆 **派发（字节码）**、**整数表示**、**调用/帧**、**分配与 RC**；禁止只答「解释器慢」。
- GIL 下 CPU 密集多线程为何不加速；I/O 与释 GIL 扩展为何可以。
- `PyObject*` 借引用 vs 新引用；扩展里漏 `Py_DECREF` 的典型后果。
- PyPy 与 CPython 数字不可比时缺了什么：warmup、与 C-API 兼容度、分配路径。
- 列表存一万个 int 的内存图：指针数组 + 各 `PyLongObject`（及缓存命中否）。
- `async` 不提供并行；并行要落到进程、释 GIL 的 C、或自由线程构建。

JavaScript 在生产引擎（V8、JavaScriptCore、SpiderMonkey）里走解释/基线编译与优化编译接力，对象模型是动态形状与隐藏类，堆由追踪式 GC 管理。TypeScript 在编译期擦除类型，发出的仍是 JavaScript：运行时语义与性能边界以 JS 引擎为准。轴见 [求值与执行模型](../ch04/evaluation.md)、[类型系统轴](../ch04/typing.md)、[GC 机制](../ch04/gc-mechanics.md)。

### 实现谱系与执行管线

源码经解析生成字节码或立即进基线编译器；热点由优化编译器（V8 的 Turbofan 等）基于类型反馈生成机器码，投机失败则 **deopt** 回解释/基线。内联缓存（IC）把属性负载与调用位点的历史形状打到快速路径；这是动态语言里「看似解释、稳态近直连」的机制，与 Java 的类型剖面同族但对象模型不同。

浏览器与 Node/Bun/Deno 嵌入同一类引擎，差别在宿主 API、事件循环与系统绑定，不在「JS 有没有 JIT」。AOT 或快照（代码缓存、V8 快照）缩短启动，不取消优化编译与 deopt。基准必须声明引擎与是否已 warmup，见执行模型轴。

事件循环：宏任务与微任务队列推进；`async`/`await` 是 Promise 上的状态机语法糖。CPU 密集工作占满调用栈会饿死循环；Worker 是另外的隔离堆与消息拷贝/转移。

### 内存与对象表示

对象是属性袋：引擎用隐藏类（map/shape）把偏移固定下来，走 IC 快速负载；形状突变（加属性、改原型）导致转换与可能的 deopt。元素与命名属性可分不同存储；数组是元素密集时的优化形态，空洞数组走慢路径。数值在引擎里常为 IEEE 754 双精度；部分引擎对整型值做 tagged 或 Smi 特化优化，但语言语义仍是 Number（另有 `BigInt`）。

字符串不可变；拼接与子串策略因引擎而异。闭包捕获变量到环境对象，是分配源。原型链查找在 IC 未命中时沿链走；`__proto__` 变更摧毁形状假设。布局直觉见 [对象布局](../ch04/object-layout.md)：JS「没有固定 struct 布局」直到引擎给它形状。

装箱：原始值经临时包装对象调方法；引擎通常优化掉可见分配。与 `object` 字段、字典模式对象相比，稳定形状对象更接近「固定偏移」。GC 为追踪式分代/增量/并发变体，写屏障与分配在字段写入中现身，见 [写屏障](../ch04/gc-mechanics.md)。

### TypeScript 作为擦除层

TypeScript 提供静态名义/结构混合的检查与编辑器证据，**emit 时擦除类型**（`enum`、命名空间等少数特性会留下运行时代码）。`strict` 空检查、判别联合、`satisfies` 等不生成运行时断言，除非手写或使用装饰器/emit 辅助。渐进类型轴上的结论：编译期拒绝一类错误，运行时仍是 JS 的动态派发与自动转换。

因此「TypeScript 更快」默认不成立；更快只可能来自：更可预测的代码形状便于 IC、或配合更优算法/数据结构，而不是类型本身留在 VM 里。与 Kotlin/JVM 不同，TS 不把泛型擦到另一套带对象头的字节码类型系统——它擦到无类型的 JS。

### 并发与运行时调度

主线程单调用栈 + 事件循环；并行靠 Worker、或宿主线程中的原生扩展。SharedArrayBuffer 与 `Atomics` 提供共享内存与等待/通知；普通对象不共享于 Worker 之间。模型是「单线程运行时 + 消息/共享字节缓冲」，见 [并发模型](../ch04/concurrency.md)。

`async` 不创造线程；微任务在当前宏任务末尾排空。长时间同步循环会同时挡住 UI 与 I/O 回调——这是宿主语义，不是 JIT 质量问题。

### 与 C / ABI 的边界

在 Node 中，**N-API** / **node-addon-api** 与历史 V8 API 把 C/C++ 接到 JS 值：句柄范围（handle scope）管理本地引用寿命，避免 GC 回收仍被本地持有的值，见 [FFI](../ch04/ffi.md)。`napi_create_external` 一类把 C 寿命与 JS 包装对象绑定。浏览器侧 WASM 提供线性内存与表格调用，JS↔WASM 边界有类型与拷贝成本；DOM 与平台 API 是宿主绑定而非 C ABI。

字符串与数组缓冲跨边界常拷贝或移交（`ArrayBuffer` transfer）。异常：JS 异常与 C++ 异常、napi 状态码之间需显式转换。Worker 里扩展要考虑线程安全；许多原生库假定只在主线程调用。

### 影响正确性与性能的语义

`==` 的强制转换、`===` 的严格相等、以及 `ToPrimitive` 规则制造「看起来正确」的分支；性能敏感路径用严格相等与显式转换。`Number` 超过 \(2^{53}-1\) 整数安全范围后不能精确表示所有整数；算法级 fib 若依赖精确大整数应走 `BigInt`（慢路径，语义不同）。

尾调用优化在 ES 规范有入口，引擎实现参差；不可依赖深度递归被擦成循环。对象形状稳定时 IC 命中，性能可接近单态；多态位点与 megamorphic 状态使调用退回慢查。隐藏类与 deopt 是读火焰图时的常见解释项。

原型污染、可变共享对象、以及模块求值顺序（循环依赖的暂时死区）属于正确性语义；与 [UB 抽象机](../ch04/ub-abstract-machine.md) 不同，JS 更常给出明确但令人惊讶的结果，而不是许可编译器任意删检查——直到进入 WASM/原生扩展的 UB 域。

### 导师对话笔记

- 解释「JS 也能很快」：IC + 隐藏类 + 优化编译；追问 deopt 原因（形状突变、类型反馈失败）。
- TypeScript 类型在运行时是否还在：默认不在；特例 emit 要能举 `enum`。
- `Number` vs `BigInt` vs 引擎 Smi：语言语义与表示优化分层说。
- 事件循环：微任务与宏任务顺序；`await` 之后的续体何时跑。
- N-API 句柄寿命；把裸指针存进 JS 又在 GC 后用的故障模式。
- 跨引擎/跨运行时（Node vs Bun）比分差时，先对齐是否同算法、同整数语义、同 warmup。

四门语言常被放进同一张「动态/脚本」桌子，但默认执行管线与内存纪律差得很远。下面用同一组轴做一次对照样本：谁在字节码循环里、谁在请求结束时扔掉整个堆、谁用 isolate 换共享内存、谁用惰性求值与写时复制把向量语义做成语言核心。轴的定义不重讲，见 [求值与执行模型](../ch04/evaluation.md)、[内存管理轴](../ch04/memory-management.md)、[并发模型](../ch04/concurrency.md)。

### 一条轴上的四种落点

**Ruby（CRuby / YARV）** 把程序编成 YARV 字节码，由虚拟机解释；对象为堆上 tagged 值与 RVALUE 槽位，GC 为追踪式（兼压缩等演进）。全局虚拟机锁（GVL）使多数 Ruby 字节码同一时刻只在一个原生线程上推进——与 CPython GIL 同族：CPU 密集线程不加速，I/O 与显式释锁的 C 扩展可重叠。方法派发经内联缓存沿祖先链查找；猴子补丁与 `method_missing` 使缓存失效成为性能叙事的一部分。整数可从立即数扩到 Bignum；调用与块（closure）分配频繁。C 扩展经 Ruby C API 持有对象引用，须按 GC 与 GVL 规则销账，见 [FFI](../ch04/ffi.md)。

**PHP（Zend）** 的经典部署单位是**请求**：FPM/Apache 模块等模型下，请求开始时初始化执行器，结束时释放请求范围的分配——生命周期本身就是粗粒度回收器。Zend 引擎执行操作码；对象与数组（HashTable）带引用计数，写时分离（copy-on-write）让赋值便宜直到写入。OPCache 把编译结果留在共享内存，跨请求复用，使「每次请求都从源码解析」不再成立。并发通常落在多进程/多请求工人，而不是语言内共享堆多线程；线程扩展存在但不是默认心智模型。与 C 的边界是 Zend 扩展 API 与 `FFI` 扩展；请求结束时悬空的本地资源必须在 RSHUTDOWN 一类钩子里收干净。对话时 PHP「快不快」常混进网关、OPCache 命中与框架引导，而不只是操作码派发。

**Dart** 把同一套语言切到不同后端：开发期 JIT（热重载、快速迭代），发布期 **AOT** 编成机器码（Flutter 移动发布的主路径）；另有 JavaScript 后端与 Dart VM isolate 模型。内存以追踪式 GC 管理；**isolate** 不共享可变堆，只靠消息传递（及部分 typed data 转移）——归 actor/CSP 一侧，而不是多线程抢同一对象图，见并发轴。整数在语言里是任意精度抽象，实现可对小整数优化；相对 JS `Number` 的语义切口不同。FFI（`dart:ffi`）按 C ABI 调本地库，并需处理 Dart GC 与本地指针的寿命。读基准时必须声明：JIT 升温后的 VM、AOT 发布构建，还是编译到 JS 后的引擎——三者数字不可直接并排当同一「Dart」。

**R** 面向统计计算：向量与列表是一等公民，大量操作是整向量原语而不是标量循环。求值默认**惰性**（promise）：参数延迟到需要时再强制，配合按需更新与作用域链。对用户可见的「赋值」常走写时复制：共享底层数据直到修改，使函数参数看起来像值传递而不付全拷贝。标量在 R 里往往是长度为 1 的向量；朴素标量递归 fib 既打在解释/调用开销上，也打在「没用向量化引擎」上。内存由 GC 管理；与 C/Fortran 数值库的边界（`.Call` / `.Fortran`）是性能出口，和 Python→NumPy 同构——快在离开解释循环的那段。并行靠多进程或显式并行包，语言默认单线程求值。

四者对比时，用「是不是动态类型」只能得到弱分类。更稳的切口是：

| 样本 | 默认执行 | 默认并发叙事 | 回收与寿命 |
| --- | --- | --- | --- |
| Ruby | YARV 字节码解释 + IC | 线程 + GVL | 追踪 GC；对象跨请求/进程长寿 |
| PHP | Zend 操作码；常 + OPCache | 多进程请求工人 | 请求级 arena 式释放 + RC/COW |
| Dart | JIT 与 AOT 双主路径 | isolate 消息传递 | 每 isolate 追踪 GC |
| R | 解释 + 向量原语；惰性 promise | 单线程为主；数值进本地库 | GC；COW 向量语义 |

### 同算法路径上的常见差异

若用朴素递归 fib 一类标量算法压四者，Ruby/PHP/R 主要暴露字节码/解释派发、调用约定与装箱或向量盒子开销；PHP 还叠请求引导是否计入；R 额外暴露「没用向量化」的错位。Dart AOT 更接近托管静态语言的调用与分配形态，JIT 路径则要算 warmup。把 [benjdd.com/languages](https://benjdd.com/languages/) 一类榜单当问题清单时，应追问：是否测到了 PHP 的请求外开销、Dart 的 AOT 还是 JIT、R 是否在标量递归上与语言设计意图错位——而不是把名次当成实现质量排序。

C·ABI 距离：四者都能调 C，但默认「热路径是否已在 C」不同。Ruby/PHP 扩展与 R 的 `.Call` 常把热点挪出 VM；Dart FFI 显式；若基准内核已在本地库，排名测的是库而不是语言表面。

### 导师对话笔记

- 用 GVL/GIL、请求生命周期、isolate、惰性+COW 四条术语区分样本，避免「都是脚本语言」收场。
- PHP 请求结束释放与长驻 Ruby/Dart 进程的泄漏形态不同：前者掩盖跨请求泄漏，后者暴露。
