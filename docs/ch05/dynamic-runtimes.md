# 动态运行时样本：Ruby、PHP、Dart、R

四门语言常被放进同一张「动态/脚本」桌子，但默认执行管线与内存纪律差得很远。下面用同一组轴做一次对照样本：谁在字节码循环里、谁在请求结束时扔掉整个堆、谁用 isolate 换共享内存、谁用惰性求值与写时复制把向量语义做成语言核心。轴的定义不重讲，见 [求值与执行模型](../ch04/evaluation.md)、[内存管理轴](../ch04/memory-management.md)、[并发模型](../ch04/concurrency.md)。

## 一条轴上的四种落点

**Ruby（CRuby / YARV）** 把程序编成 YARV 字节码，由虚拟机解释；对象为堆上 tagged 值与 RVALUE 槽位，GC 为追踪式（兼压缩等演进）。全局虚拟机锁（GVL）使多数 Ruby 字节码同一时刻只在一个原生线程上推进——与 CPython GIL 同族：CPU 密集线程不加速，I/O 与显式释锁的 C 扩展可重叠。方法派发经内联缓存沿祖先链查找；猴子补丁与 `method_missing` 使缓存失效成为性能叙事的一部分。整数可从立即数扩到 Bignum；调用与块（closure）分配频繁。C 扩展经 Ruby C API 持有对象引用，须按 GC 与 GVL 规则销账，见 [FFI](../ch04/ffi.md)。

**PHP（Zend）** 的经典部署单位是**请求**：FPM/Apache 模块等模型下，请求开始时初始化执行器，结束时释放请求范围的分配——生命周期本身就是粗粒度回收器。Zend 引擎执行操作码；对象与数组（HashTable）带引用计数，写时分离（copy-on-write）让赋值便宜直到写入。OPCache 把编译结果留在共享内存，跨请求复用，使「每次请求都从源码解析」不再成立。并发通常落在多进程/多请求工人，而不是语言内共享堆多线程；线程扩展存在但不是默认心智模型。与 C 的边界是 Zend 扩展 API 与 `FFI` 扩展；请求结束时悬空的本地资源必须在 RSHUTDOWN 一类钩子里收干净。对话时 PHP「快不快」常混进网关、OPCache 命中与框架引导，而不只是操作码派发。

**Dart** 把同一套语言切到不同后端：开发期 JIT（热重载、快速迭代），发布期 **AOT** 编成机器码（Flutter 移动发布的主路径）；另有 JavaScript 后端与 Dart VM isolate 模型。内存以追踪式 GC 管理；**isolate** 不共享可变堆，只靠消息传递（及部分 typed data 转移）——归 actor/CSP 一侧，而不是多线程抢同一对象图，见并发轴。整数在语言里是任意精度抽象，实现可对小整数优化；相对 JS `Number` 的语义切口不同。FFI（`dart:ffi`）按 C ABI 调本地库，并需处理 Dart GC 与本地指针的寿命。读基准时必须声明：JIT 升温后的 VM、AOT 发布构建，还是编译到 JS 后的引擎——三者数字不可直接并排当同一「Dart」。

**R** 面向统计计算：向量与列表是一等公民，大量操作是整向量原语而不是标量循环。求值默认**惰性**（promise）：参数延迟到需要时再强制，配合按需更新与作用域链。对用户可见的「赋值」常走写时复制：共享底层数据直到修改，使函数参数看起来像值传递而不付全拷贝。标量在 R 里往往是长度为 1 的向量；朴素标量递归 fib 既打在解释/调用开销上，也打在「没用向量化引擎」上。内存由 GC 管理；与 C/Fortran 数值库的边界（`.Call` / `.Fortran`）是性能出口，和 Python→NumPy 同构——快在离开解释循环的那段。并行靠多进程或显式并行包，语言默认单线程求值。

四者对比时，用「是不是动态类型」只能得到弱分类。更稳的切口是：

| 样本 | 默认执行 | 默认并发叙事 | 回收与寿命 |
| --- | --- | --- | --- |
| Ruby | YARV 字节码解释 + IC | 线程 + GVL | 追踪 GC；对象跨请求/进程长寿 |
| PHP | Zend 操作码；常 + OPCache | 多进程请求工人 | 请求级 arena 式释放 + RC/COW |
| Dart | JIT 与 AOT 双主路径 | isolate 消息传递 | 每 isolate 追踪 GC |
| R | 解释 + 向量原语；惰性 promise | 单线程为主；数值进本地库 | GC；COW 向量语义 |

## 同算法路径上的常见差异

若用朴素递归 fib 一类标量算法压四者，Ruby/PHP/R 主要暴露字节码/解释派发、调用约定与装箱或向量盒子开销；PHP 还叠请求引导是否计入；R 额外暴露「没用向量化」的错位。Dart AOT 更接近托管静态语言的调用与分配形态，JIT 路径则要算 warmup。把 [benjdd.com/languages](https://benjdd.com/languages/) 一类榜单当问题清单时，应追问：是否测到了 PHP 的请求外开销、Dart 的 AOT 还是 JIT、R 是否在标量递归上与语言设计意图错位——而不是把名次当成实现质量排序。

C·ABI 距离：四者都能调 C，但默认「热路径是否已在 C」不同。Ruby/PHP 扩展与 R 的 `.Call` 常把热点挪出 VM；Dart FFI 显式；若基准内核已在本地库，排名测的是库而不是语言表面。

## 导师对话笔记

- 用 GVL/GIL、请求生命周期、isolate、惰性+COW 四条术语区分样本，避免「都是脚本语言」收场。
- PHP 请求结束释放与长驻 Ruby/Dart 进程的泄漏形态不同：前者掩盖跨请求泄漏，后者暴露。
- Dart 数字要钉构建模式；Flutter debug/profile/release 不是同一执行管线。
- R 的快来自向量化与底层 BLAS/Lapack 一类路径；标量递归基准回答不了数据分析工作负载。
- 与 Python/JS 对照时，先并到同一轴（执行、内存、并发），再谈社区与框架。
