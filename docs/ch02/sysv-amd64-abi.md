# System V AMD64 ABI

Linux 用户态 x86-64 程序的函数如何传参、返回、对齐栈，由 System V AMD64 ABI（常称 SysV）约定。编译器、手写汇编与 FFI 必须说同一种约定，否则参数会落在错误的寄存器或栈槽上。

## 整数与指针参数

前六个整数或指针参数依次使用：

`rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9`

更多参数从右向左压栈。64 位返回值在 `rax`；128 位整数返回值使用 `rax:rdx`。被调用方通过 `%al`（或整体约定中的可变参数规则）获知可变参数里向量寄存器的使用情况：对 varargs 函数，调用方把使用的 SSE 寄存器个数写入 `al`。

## 浮点与向量参数

浮点与部分向量参数走 XMM：`xmm0`–`xmm7` 传前八个，返回值在 `xmm0`（更大对象另有规则）。口试常问「两个 `double` 参数走哪」：答案是 `xmm0` 与 `xmm1`，而不是 `rdi`/`rsi`。

## 栈对齐、红区与保存寄存器

调用 `call` 执行后（返回地址已入栈），进入被调函数时 `rsp` 应对齐到 16 字节边界。叶函数可以在 `rsp` 下方 128 字节的 **red zone** 里暂存而不显式调整 `rsp`，信号与中断处理会避开这块区域的破坏约定；非叶函数或可能被信号打断且自身依赖红区的写法需要更谨慎，编译器对叶函数的利用最常见。

调用者保存（caller-saved / volatile）：`rax`, `rcx`, `rdx`, `rsi`, `rdi`, `r8`–`r11`，以及 XMM 等。被调用者保存（callee-saved）：`rbx`, `rbp`, `r12`–`r15`。被调函数若使用后者，必须先保存再返回前恢复。

## 结构体与内存中的参数

小型结构体可能拆进寄存器；过大或含特殊字段的对象通过栈或隐藏指针传递/返回（返回时调用方分配空间，地址常入 `rdi`，此时其余参数右移）。跨语言 FFI 必须确认双方对布局、对齐与是否「按值拆寄存器」的理解一致，否则会在看起来「类型差不多」的结构体上翻车。

## 一次 `call` 的时间线

1. 调用方把参数放入约定寄存器/栈，按需保存自己的 caller-saved 活值。  
2. `call` 压入返回地址，跳转到目标。  
3. 被调方按需建立帧（`push rbp` / `mov rbp, rsp` 等）、保存 callee-saved、分配局部与溢出区。  
4. 返回值写入 `rax` / `xmm0` 等，恢复保存的寄存器，`ret` 弹出返回地址。

结合 [过程调用与栈帧](stack-frames.md) 里的 prologue/epilogue 看反汇编，可以把寄存器表变成具体指令序列。

## AArch64 AAPCS64 对照

AArch64 用户态常见约定（AAPCS64）用 `x0`–`x7` 传前八个整数/指针参数，返回值在 `x0`（及 `x1`）；浮点用 `v0`–`v7`。链路寄存器 `x30`（LR）保存返回地址，通常不靠栈完成「纯叶调用」的返回地址传递。栈同样有对齐要求（通常 16 字节）。与 SysV 对照时，先画「第 n 个整型参数在哪个寄存器」，再比返回地址保存在哪里；细节以平台文档为准，本站主线实验仍在 SysV 上完成。
