# 位置无关代码与动态链接

共享库与现代 PIE 可执行文件需要在装载时被放到未预先固定的虚拟地址上。代码里对全局数据与外部函数的引用，因此不能写成「绝对地址立即数」，而要经过 **RIP-relative 寻址**、**GOT（Global Offset Table）** 与 **PLT（Procedure Linkage Table）** 一类机制，在运行期绑到真实地址。

## PIC 的直观形态

位置无关代码用相对当前指令指针的偏移访问常量池与 GOT 槽。x86-64 上常见 `movq symbol@GOTPCREL(%rip), %rax` 再间接取址，或对已知同模块符号直接 `lea symbol(%rip), %rax`。链接器与装载器负责把相对引用填成正确的运行时地址；`-fPIC` / `-fPIE` 改变的是编译器选择的寻址与重定位类型，从而改变 `objdump` 里看到的指令形态。

## GOT

GOT 是一块在数据段中的地址表。每个需要动态解析的符号对应一个槽，装载或解析完成后槽内是该符号的绝对地址。访问跨模块全局变量时，代码先从 GOT 读出指针，再访问对象——多一次内存间接，换来地址可在装载时统一修补。

## PLT 与懒绑定

对外部函数的调用常进入本模块的 PLT 桩：第一次调用跳到动态链接器（`ld.so`）的解析例程，解析成功后把目标地址写进对应的 GOT 槽，并把 PLT 后续入口改成直接跳到该地址；之后再调用同一 PLT 项就接近「一次间接跳」。懒绑定把解析成本推迟到第一次调用；`LD_BIND_NOW` 一类设置可改为启动时全部绑定。

口试叙述一条外部调用路径时，按顺序说清即可：`call foo@PLT` → PLT 桩 →（首次）动态链接器写 GOT → 此后经 GOT 到 `foo` 真身。懒绑定前后 **GOT 槽内容不同**：解析前指向解析器路径，解析后指向最终函数。

## 与静态链接的分工

静态链接在链接期把目标文件与归档库拼成一个映像，重定位大多在链接期完成。动态链接把一部分重定位留到装载/首次调用，并允许多个进程共享库的文本段。细节见 [静态链接与符号解析](static-linking.md)、[重定位](relocation.md)、[可执行文件装载](loading.md)。
