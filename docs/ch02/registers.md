# 寄存器与标志位

x86-64 整数状态对汇编读者可见的部分，主要是十六个通用寄存器、指令指针 `RIP`、栈指针 `RSP`，以及标志寄存器 `RFLAGS` 中与条件码相关的若干位。向量与浮点状态在 `XMM`/`YMM`/`ZMM` 与 MXCSR 中；调用约定如何使用它们见 [SysV ABI](sysv-amd64-abi.md)。本页建立读写这些名字时的默认语义，并预告调用者/被调用者保存划分。

## 通用寄存器

十六个 64 位通用寄存器：`RAX`、`RBX`、`RCX`、`RDX`、`RSI`、`RDI`、`RBP`、`RSP`、`R8`–`R15`。每个都可按宽度取子视图；写 32 位子寄存器时，硬件将高 32 位清零。

| 64 位 | 32 位 | 16 位 | 8 位（低） |
| --- | --- | --- | --- |
| `%rax` | `%eax` | `%ax` | `%al` |
| `%rbx` | `%ebx` | `%bx` | `%bl` |
| `%rcx` | `%ecx` | `%cx` | `%cl` |
| `%rdx` | `%edx` | `%dx` | `%dl` |
| `%rsi` | `%esi` | `%si` | `%sil` |
| `%rdi` | `%edi` | `%di` | `%dil` |
| `%rbp` | `%ebp` | `%bp` | `%bpl` |
| `%rsp` | `%esp` | `%sp` | `%spl` |
| `%r8` | `%r8d` | `%r8w` | `%r8b` |
| … | … | … | … |
| `%r15` | `%r15d` | `%r15w` | `%r15b` |

历史别名仍出现在机器码与文档里：`%rax` 常作返回值与某些指令的隐式操作数；`%rdx:%rax` 组成除法与宽乘法的 128 位对；`%rcx` 作串指令计数与移位计数；`%rdi`/`%rsi` 作串指令的目的/源指针。这些隐式用法与 ABI 参数分工重叠，读 `objdump` 时两者要一起看。

在 System V AMD64 用户态约定下，整数/指针参数按顺序使用 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9`；返回值主要在 `%rax`（次宽整数可进 `%rdx`）。这是约定层，不是 ISA 强制；换调用约定后同一条 `mov` 语义不变，只是「谁在调用边界活着」变了。

## RIP 与 RSP

`RIP` 是下一条将执行指令的地址。x86-64 用户态不能像通用寄存器那样用 `movq %rip, %rax` 直接读写；读取当前 PC 的常见办法是 `lea` 的 RIP-relative 形式，或依赖 `call` 压栈的返回地址。控制转移指令（`jmp`/`call`/`ret`/`jcc`）通过改写 `RIP` 改变执行位置；编码细节见 [指令编码与 RIP 相对寻址](encoding-rip-relative.md)。

`RSP` 指向栈顶。`push` 先把 `RSP` 减去操作数宽度再写入；`pop` 先读再加回。`call` 等价于把返回地址压栈并跳转；`ret` 弹出到 `RIP`。栈向低地址增长：

```text
高地址
  ...
  旧栈帧
  返回地址      ← call 之后，(%rsp) 指向这里
  被保存的寄存器 / 局部量
  ...
低地址          ← %rsp
```

叶子函数在一定条件下可使用 `%rsp` 下方的红区而不显式减法，规则见 [栈帧](stack-frames.md) 与 [SysV ABI](sysv-amd64-abi.md)。

`RBP` 在未优化代码里常作帧指针：prologue 保存旧 `%rbp` 并把 `%rbp` 设为当前帧基址，局部变量用负偏移、参数用正偏移寻址。`-O` 以上编译器常省略帧指针，改用 `%rsp` 相对寻址，调试时局部变量位置随 `%rsp` 变化而变。

## RFLAGS 中的条件码

算术与逻辑指令更新 `RFLAGS` 中的条件码；条件跳转与条件传送读取这些位。与整数比较直接相关的四位：

| 标志 | 含义（典型） |
| --- | --- |
| `CF` | 无符号进位/借位 |
| `ZF` | 结果为零 |
| `SF` | 结果符号位为 1 |
| `OF` | 有符号溢出 |

`cmp a, b` 按 \(b - a\) 的语义更新标志但不写回差（AT&T 下是 `cmp src, dst` 计算 `dst - src`）。`test a, b` 按 `a & b` 更新标志，常用于测位或与零比较。条件跳转助记符直接编码对这些标志的谓词，例如 `je`/`jz` 看 `ZF`，`jl` 看有符号小于，`jb` 看无符号低于；完整表见 [控制流与条件码](control-flow.md)。

`addq`、`subq`、`andq`、`xorq` 等也会改标志；`lea` 只做地址计算，**不**改标志。需要「算地址且保留标志」或「算地址且避免改标志」时，二者不可互换。

## 调用者保存与被调用者保存

跨 `call` 边界，寄存器分成两组（System V AMD64）：

**调用者保存**（caller-saved，又称 volatile）：`%rax`、`%rcx`、`%rdx`、`%rsi`、`%rdi`、`%r8`–`%r11`，以及 XMM0–XMM15 等。被调用方可任意破坏；调用方若在 `call` 之后还需要其中的值，必须自己先存到栈或被调用者保存寄存器。

**被调用者保存**（callee-saved，又称 non-volatile）：`%rbx`、`%rbp`、`%r12`–`%r15`。被调用方若使用，必须在返回前恢复原值；调用方可以假定它们跨调用存活。

分组的动机是降低总溢写：叶子函数多用调用者保存寄存器可少做 prologue/epilogue；深调用链上的长生命周期值放在被调用者保存寄存器，避免每个调用点都保存。完整表与浮点、变参规则写在 [SysV ABI](sysv-amd64-abi.md)；[栈帧](stack-frames.md) 演示 prologue 如何 `push` 被调用者保存寄存器。

## 宽度后缀与零扩展

AT&T 助记符用 `b`/`w`/`l`/`q` 标宽度：`movb`、`movw`、`movl`、`movq`。写 `%eax` 的 `movl` 会清零 `%rax` 的高 32 位；写 `%al` 的 `movb` 只改低 8 位。从窄到宽需要显式扩展：`movzbl`（零扩展）、`movsbl`（符号扩展）等。C 里「窄参数在寄存器中如何呈现」由 ABI 规定为已扩展到 32/64 位的视图；手写汇编时与编译器输出保持同一约定，可避免高位垃圾进入比较。
