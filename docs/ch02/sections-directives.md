# 段、符号与汇编器指令

汇编源文件同时描述两类事物：指令与数据的**内容**，以及它们在目标文件里落入哪一**段**、对外可见性如何、对齐约束是什么。汇编器把段指令翻译成 ELF 节区（section）与符号表项；链接器再按节区属性合并、重定位并映射到可装载段（segment）。本页只处理静态汇编里最常用的一组指令；ELF 头与程序头的完整字段见 [ELF 文件结构](elf.md)。

## 三类内容段

可重定位目标文件里，与用户代码直接对应的内容通常落在三类节区。分类轴是「装载后是否占文件空间、是否可写」。

`.text` 存放机器指令，装载后一般映射为可读可执行、不可写。函数体、跳转目标标签默认写在这里：

```asm
    .text
    .globl  add1
    .type   add1, @function
add1:
    leaq    1(%rdi), %rax
    ret
```

`.data` 存放已初始化的可写数据。全局/静态变量的初值以字节形式进入目标文件，装载时从文件拷贝到可写页：

```asm
    .data
    .align  8
    .globl  g_count
g_count:
    .quad   42
```

`.bss` 存放未初始化（或显式为零）的可写数据。节区在文件中不占对应的数据字节，只记录需要的尺寸；装载器在进程里分配并清零。GAS 用 `.comm` / `.lcomm` 或 `.bss` 加 `.zero` / `.skip` 声明：

```asm
    .bss
    .align  8
buf:
    .zero   4096
```

只读常量常落在 `.rodata`（字符串字面量、`const` 全局量）。它与 `.text` 一样不可写，但通常不可执行；链接脚本与编译器也可能把字面量并进其他只读节。读写属性由节区标志决定，不由节区名字的文学含义单独保证——检视时以 `readelf -S` 的 `W`/`A`/`X` 标志为准。

## 符号与可见性

标签在汇编里是地址的名字。汇编器为每个标签生成符号表项；链接器按绑定与类型解析跨文件引用。

`.globl name`（GAS 亦接受 `.global`）把 `name` 标为全局绑定：本目标文件定义、其他目标文件可引用。缺少 `.globl` 的标签默认局部，链接阶段对外不可见，可与其他文件中的同名局部符号共存。

`.type name, @function` / `@object` 写入符号类型，供链接器与调试器区分函数与数据。手写小实验时常可省略，但与 C 目标文件混链时补上可减少工具误判。

`.size name, .-name` 用「当前位置减去符号起点」写出符号大小，常见于函数末尾。`nm` / `readelf -s` 里的 size 列由此而来。

弱符号用 `.weak`；未解析时可保留为 0 或被强定义覆盖。动态库与弱引用的解析规则放到 [静态链接](static-linking.md) 与 [PIC](pic-dynamic.md)。

## 对齐与填充

对齐约束写在定义之前，作用于随后的位置计数器。`.align n` 在 GAS 的 x86-64 ELF 目标上通常把地址对齐到 \(2^n\) 字节（与某些平台把参数当成字节数的语义不同；写可移植宏时需核对 `as` 手册）。`.p2align n` 语义明确为对齐到 \(2^n\)。

```asm
    .data
    .p2align 3          # 8 字节对齐
vec:
    .quad   1, 2, 3, 4
```

对齐不足时，硬件可能产生对齐故障（某些访存），或仅损失性能（x86 多数普通访存允许未对齐但更慢）。ABI 对栈、向量参数、某些结构体字段另有对齐要求，见 [SysV ABI](sysv-amd64-abi.md)。汇编器在 `.align` 与下一条内容之间插入填充：代码段常用 `nop` 类填充，数据段用零。

`.balign 16` 把地址对齐到 16 字节边界（参数为字节数）。与 `.p2align` 对照阅读比死记名字可靠：一个吃幂次，一个吃字节数。

## 位置计数器与局部标签

`.` 表示当前位置计数器。`.-foo` 计算从标签 `foo` 到当前位置的距离，常用于 `.size` 与手工重定位距离。

GAS 数字局部标签 `1:`、`2:` 可重复出现；引用写成 `1b`（backward）或 `1f`（forward），避免为每个基本块发明全局唯一名：

```asm
    cmpq    %rsi, %rdi
    jle     1f
    movq    %rdi, %rax
    ret
1:
    movq    %rsi, %rax
    ret
```

## 与 ELF 节区的对应

汇编里的「段」在目标文件中首先是**节区**。典型映射：

| 汇编方向 | ELF 节区（常见） | 装载后权限（常见） |
| --- | --- | --- |
| `.text` | `.text` | `r-x` |
| `.data` | `.data` | `rw-` |
| `.bss` | `.bss` | `rw-`（文件尺寸为 0） |
| 只读常量 | `.rodata` | `r--` |
| 符号/重定位 | `.symtab`、`.rela.text` 等 | 不装载到运行时映像，或仅链接期使用 |

链接器按节区标志合并多个 `.o` 的同名节，再把若干节区打包进程序头里的 `PT_LOAD` 段。因此「段」一词在口语里常混用：汇编器指令说的是逻辑内容桶，装载器看的是虚拟地址连续的 `PT_LOAD`。用 `readelf -S` 看节，用 `readelf -l` 看装载段，两者一起才能对上进程映像。

对 `.text` 里的外部符号引用，汇编器通常留下重定位记录（例如 `R_X86_64_PLT32`、`R_X86_64_PC32`），把最终地址交给链接器填写。[重定位](relocation.md)页说明这些记录如何改写指令中的位移字段；本页只需建立「符号名 → 节区内偏移 → 待填字节」的链条。

## 最小可汇编单元

把符号、段与对齐放在同一文件里，得到链接器可消费的最小形状：

```asm
    .text
    .globl  _start
    .type   _start, @function
_start:
    movl    $60, %eax       # SYS_exit
    xorl    %edi, %edi      # status = 0
    syscall

    .size   _start, .-_start
```

该例直接以 `_start` 为入口并使用 `syscall`，绕过 C 运行时；正常与 C 混链时入口与参数布置见 [进程入口](crt-entry.md)。下一步是弄清指令实际读写哪些寄存器：[寄存器与标志位](registers.md)。
