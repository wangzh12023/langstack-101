# 静态链接与符号解析

静态链接把若干可重定位目标文件与静态库成员拼成一个输出映像（可执行文件或共享库的中间形态）：统一分配地址、解析符号、应用重定位。动态链接把一部分工作留到装载期；本节只谈链接期完成的那一段。

## 符号解析

每个目标文件导出符号、引用未定义符号。链接器在全局符号表里匹配定义与引用。强符号通常不可重复定义；弱符号可被强定义覆盖，多个弱定义的取舍由实现与链接选项决定。C 的 `inline`、模板实例化、公共符号（COMDATs）会引入「允许多份相同定义、最终保留一份」的规则——C++ 的 ODR 与链接器的 COMDAT 折叠在此相遇。

从静态库（`.a`）抽取目标文件时，经典 Unix 链接器按「当前未定义符号集合」迭代拉取成员，未引用到的 `.o` 可不进入最终映像。循环依赖有时需要重复指定库或使用 `--start-group` 一类选项。

## 布局与入口

链接脚本（或目标平台的默认脚本）决定节的合并顺序与段的对齐、权限。可执行文件的入口符号通常是 `_start`（或等价名），不是 `main`；C 运行时再从 `_start` 走到 `main`，见 [进程入口与 C 运行时](crt-entry.md)。

解析完成后，链接器按 [重定位](relocation.md) 记录改写机器码与数据中的地址字段。输出若仍含动态符号依赖，则留下动态节与待装载重定位，供 [可执行文件装载](loading.md) 使用。

## 与「最终地址」相关的可见差

同一份源码，静态链接进主程序的函数调用可变成直接 `call rel32`；链成共享库并被其他模块调用时，往往经 PLT/GOT。比较 `nm`、`readelf -s` 与 `objdump -d` 可以看到：符号是否局部、是否隐藏、调用是否间接。
